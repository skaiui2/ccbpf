# Execution-migration experiments

[English migration guide](../../docs/English/execution-migration.md) · [中文迁移文档](../../docs/中文/执行迁移设计与复现.md) · [System paper](../../docs/papers/ccBPF-Compiler-Runtime-and-Migration.pdf)

Run from the repository root with Python 3 and a GCC-compatible compiler:

```sh
python experiments/migration/run_experiments.py --cc gcc --out /tmp/ccbpf-migration-results
```

On Windows, use PowerShell with MinGW GCC on `PATH`:

```powershell
python experiments/migration/run_experiments.py --cc gcc --out "$env:TEMP\ccbpf-migration-results"
```

If GCC is not on `PATH`, replace `gcc` with the full path to `gcc.exe` from your toolchain. CLion's bundled MinGW compiler can also be used. Python 3's standard library is sufficient; no Python packages are required.

## Files

| File | Purpose |
| --- | --- |
| `migration_reproduce.c` | Single-workload continuation check using the root `migrate.bpf`, including owned-image compilation and full-state comparison. |
| `suite.c` | Checkpoint restoration, repeated movement, arithmetic oracles, validation checks, allocation balance, and timing. |
| `process.c` | Source-process exit followed by destination-process restoration through a file. |
| `run_experiments.py` | Generates 32 workloads, builds `-Os` and `-O2` variants, runs the tests, and writes results outside the repository. |
| `results/2026-10-04/` | Original recorded CSV data, summary metadata, and timing plot used by the paper. |

`suite.c` checks every reached instruction boundary against a baseline and independent expected returns, repeated restoration, allocation balance, negative codec/loader inputs, and batched host operation times. `process.c` transfers the README workload through a file between independent processes. Both reuse the owned-image compilation helper from `migration_reproduce.c`; the original compiler and VM are linked unchanged.

The seeded 32-program corpus and both optimization levels are generated by `run_experiments.py`. See `results/2026-10-04/summary.json` for source hashes, platform, commands and results. CSV files contain all correctness, timing and allocation records. Generated inputs, logs, checkpoint buffers and executables belong in the external output directory, not in the repository. One host series does not measure physical-board migration latency or failure recovery.

The recorded metadata retains the paths and source hashes from the original run, before the reproduction helper was moved into this directory. New runs record its current path and the updated harness hashes; the compiler and VM sources are unchanged by this reorganization. Timing varies between runs; semantic assertions and state comparisons determine correctness.

## 中文运行说明

在仓库根目录运行上面的命令即可完成全部主机实验。Windows 可使用 CLion 自带的 MinGW `gcc.exe`；不在 `PATH` 中时，将 `--cc` 后的 `gcc` 替换为完整路径。`--out` 指向仓库外目录，生成的程序、输入、快照和日志都写入该目录。

`migration_reproduce.c` 是单个程序的独立核验，完整构建命令见[中文文档第 8 节](../../docs/中文/执行迁移设计与复现.md#8-可执行复现与结果)。`suite.c` 和 `process.c` 复用它的编译辅助函数，实验脚本负责构建和运行。

`results/2026-10-04/` 保留原始实验数据及当时的路径、源码哈希；整理目录后重新运行会记录当前路径和脚本哈希。连续性断言应通过，计时结果不要求与原记录逐项相同。主机实验没有测量板间端到端迁移耗时。
