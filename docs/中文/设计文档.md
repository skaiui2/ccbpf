# ccBPF 编译器设计文档（前端 + IR + 后端）

## 1. 总体结构

编译器整体分为三层：

- **前端（Frontend）**：词法分析、语法分析、AST 构建、类型检查、符号表管理
- **中间表示（IR）**：结构化的三地址风格指令序列
- **后端（Backend）**：IR → BPF 指令序列（4.4BSD cbpf），并最终打包为 `.ccbpf` 镜像

典型流水线：

```text
C 源码
  → 词法分析（lexer）
  → 语法分析 + AST（parser + inter）
  → IR 生成（AST.gen / jumping）
  → IR 降级为 BPF（ir_lower_program）
  → 打包为 .ccbpf（ccbpf_pack_memory）
```

## 2. 内存管理与区域划分

编译器使用 **区域分配器（region allocator）** 管理生命周期：

- `frontend_region`：词法/语法分析阶段的临时对象
- `longterm_region`：AST、类型、符号表等长期存在对象
- `ir_region`：IR 链表
- `string_region`：字符串常量池
- `backend_region`：后端布局、跳转修补等临时结构

初始化入口：

```c
void compiler_init(uint8_t region_bit,
                   uint32_t cap,
                   uint32_t string_cap,
                   uint32_t ir_cap);
```

所有 AST / Type / IR 节点均通过 `mg_region_alloc()` 从对应 region 分配，不做细粒度 free，整体在阶段结束时销毁。

## 3. 词法、语法与符号系统

### 3.1 词法分析（lexer）

`struct lexer` 负责：

- 维护当前行号、peek 字符

- 关键字表 `hashmap words`（`if/else/struct/enum/return` 等）

- token 类型枚举 

  ```
  enum tag
  ```

   覆盖：

  - 基本运算：`PLUS/MINUS/STAR/SLASH/MOD`
  - 比较：`LT/LE/GT/GE/EQ/NE`
  - 逻辑：`AND/OR/NOT`
  - 位运算：`AND_BIT/OR_BIT`
  - 标识符/常量：`ID/NUM/STRING/TRUE/FALSE`
  - 语法符号：`LPAREN/RPAREN/LBRACE/RBRACE/COMMA/SEMICOLON/LBRACKET/RBRACKET`
  - 类型/结构：`BASIC/STRUCT/ENUM`

核心接口：

```c
void lexer_init(struct lexer *lex);
struct lexer_token *lexer_scan(struct lexer *lex);
void lexer_set_input_buffer(const char *buf, size_t len);
```

### 3.2 符号与类型系统（symbols）

类型枚举：

```c
enum type_tag {
    TYPE_INT, TYPE_CHAR, TYPE_SHORT, TYPE_BOOL,
    TYPE_ARRAY, TYPE_FUNC, TYPE_PTR, TYPE_STRUCT, TYPE_ENUM
};
```

核心结构：

- `struct Type`：基础类型（tag + width）

- `struct Array`：数组类型（元素类型 + 长度）

- `struct PtrType`：指针类型（to）

- `struct StructType`：结构体，内部 `hashmap fields`，字段信息为：

  ```c
  struct StructFieldInfo {
      int offset;
      struct Type *type;
  };
  ```

- `struct EnumType`：枚举，内部 `hashmap values`

符号环境：

```c
struct Env {
    struct hashmap vars;   // 变量/参数/字段
    struct hashmap types;  // 类型名
    struct Env *prev;      // 作用域链
    int level;
};
```

提供 `env_put_var / env_put_type / env_get_var / env_get_type`，用于解析标识符、结构体字段、类型名等。

### 3.3 语法分析（parser）

`struct Parser`：

```c
struct Parser {
    struct lexer       *lex;
    struct lexer_token *look;
    struct Env         *top;
    int                 used;
};
```

主要入口：

- `parser_program()`：解析整个 C 源文件（当前只支持单个 `hook()` 函数）
- `parser_block()`：`{ ... }`
- `parser_decls()`：局部变量/结构体/枚举声明
- `parser_stmt()`：语句（if/return/赋值/空语句/块）
- `parser_bool()/join()/rel()/expr()/term()/unary()/factor()`：表达式子层级
- `parser_offset()`：数组/结构体访问偏移计算

native 函数声明通过：

```c
extern struct hashmap native_decl_table;
void native_decl_register(const char *name, int id, int argc);
```

前端只记录 `name → (id, argc)`，不关心实现。

## 4. AST 设计与表达能力

### 4.1 Node 基类与表达式/语句

所有 AST 节点都以 `Node` 为基类：

```c
struct Node {
    int  lexline;
    enum NodeTag tag;
    void (*gen)(struct Node *self, int b, int a);
    void (*jumping)(struct Node *self, int t, int f);
    char *(*tostring)(struct Node *self);
};
```

- `gen(self, b, a)`：生成 IR（`b/a` 为控制流标签，当前主要用于语句）
- `jumping(self, t, f)`：布尔表达式的条件跳转编码
- `tostring(self)`：调试用字符串表示

表达式基类：

```c
struct Expr {
    struct Node        base;
    struct lexer_token *op;
    struct Type        *type;
    int                 temp_no;  // 对应 IR 临时编号
};
```

语句基类：

```c
struct Stmt {
    struct Node base;
    int         after;   // 预留控制流用途
};
```

### 4.2 支持的表达式节点

- 常量：

  ```
  Constant
  ```

  - `int int_val;`
  - `Constant_true / Constant_false` 为单例布尔常量

- 标识符：

  ```
  Id
  ```

  - `int offset;`：在“逻辑栈帧”中的偏移（单位字节）
  - `int is_ctx_ptr;`：是否为 `ctx` 指针

- 数组访问：

  ```
  Access
  ```

  - `Expr *array; Expr *index;`
  - `int slot; int width;`（数组基址 + 元素宽度）

- ctx 访问：

  - `CtxExpr`：`ctx[offset]`，生成 `IR_LOAD_CTX`
  - `CtxPtrExpr`：`&ctx[CONST]`，仅用于一元 `&` 的受限形式

- **算术**：`Arith`（`+ - * /`）

- **一元**：`Unary`（`-` / `!`）

- **逻辑**：`Logical / And / Or / Not`

- **关系**：`Rel`（`< <= > >= == !=`）

- 字符串字面量：

  ```
  StringLiteral
  ```

  - `int str_id;`：字符串池 ID

- 内建调用 / native 调用：

  ```
  BuiltinCall
  ```

  - `const char *name;`
  - `int native_id;`
  - `int argc;`
  - `Expr *args[4];`

### 4.3 支持的语句节点

- 赋值：

  ```
  Set
  ```

  - `id = expr;` → `IR_STORE` 到对应 slot

- 数组元素赋值：

  ```
  SetElem
  ```

  - `arr[i] = expr;`，当前要求 `i` 必须是常量

- if / if-else：

  ```
  If / Else
  ```

  - 使用 `jumping()` + 显式 label + `IR_GOTO` 实现控制流

- **顺序语句**：`Seq`

- **return**：`Return`

- **空语句**：使用 `Stmt_Null` 单例表示

## 5. IR 设计与语义

### 5.1 IR 指令集

```c
enum IR_Op {
    IR_NOP,
    IR_MOVE,          // dst = imm / value
    IR_ADD, IR_SUB, IR_MUL, IR_DIV,
    IR_AND, IR_OR,
    IR_NEG, IR_NOT,

    IR_LOAD_CTX,      // dst = ctx[offset, width]
    IR_LOAD,          // dst = MEM[base + index]
    IR_STORE,         // MEM[base + index] = src

    IR_RET,           // return src1
    IR_IF_FALSE,      // if !(relop(src1, src2)) goto label
    IR_GOTO,          // goto label
    IR_LABEL,         // label definition

    IR_NATIVE_CALL,   // dst = native(native_id, args...)
};
```

关系运算：

```c
enum IR_RelOp { IR_GT, IR_GE, IR_EQ, IR_NE };
```

IR 结构：

```c
struct IR {
    enum IR_Op   op;

    int dst, src1, src2;      // 通用寄存槽（temp 编号）

    int array_base;           // 逻辑基址（0/4/8/12/...）
    int array_index;          // 逻辑偏移（当前多为 0）
    int array_width;          // 元素宽度（字节）

    enum IR_RelOp relop;      // 比较类型
    int label;                // 目标 label

    int native_id;            // native 函数 ID
    int arg_width;            // 参数宽度（当前主要用于统一 int）
    int argc;                 // 参数个数
    int args[4];              // 参数对应的 temp 编号

    struct IR *next;          // 单链表
};
```

IR 序列通过：

```c
void ir_emit(struct IR ir);
void ir_mes_get(struct ir_mes *im); // { ir_head, label_count }
```

## 6. AST -> IR 生成规则

### 6.1 临时变量分配

全局计数器：

```c
static int temp_count = 1;
int new_temp(void) { return temp_count++; }
```

每个 `Expr` 有 `temp_no`，在第一次 `expr_gen()` 时分配。所有 IR 中的 `dst/src1/src2/args[i]` 都是这个 temp 编号。

### 6.2 表达式生成（expr_gen）

核心逻辑（按 tag 分派）：

- **常量** `TAG_CONSTANT`：

  ```c
  IR_MOVE: dst = int_val;
  ```

- **标识符** `TAG_ID`：

  ```c
  IR_LOAD:
      dst         = temp_no;
      array_base  = id->offset;
      array_index = 0;
      array_width = type->width;
  ```

- **数组访问** `TAG_ACCESS`（仅支持常量下标）：

  ```c
  elem_offset = slot + idx * width;
  IR_LOAD:
      dst         = temp_no;
      array_base  = elem_offset;
      array_index = 0;
      array_width = width;
  ```

- **ctx 访问** `TAG_CTX`：

  ```c
  IR_LOAD_CTX:
      dst  = temp_no;
      src1 = offset;
      src2 = type->width;
  ```

- **字符串字面量** `TAG_STRING`：

  ```c
  str_id = intern_string(unescaped);
  IR_MOVE: dst = str_id;
  ```

- **算术** `TAG_ARITH`：

  ```c
  先递归生成 e1/e2
  IR_ADD/SUB/MUL/DIV:
      dst  = temp_no;
      src1 = e1->temp_no;
      src2 = e2->temp_no;
  ```

- **一元** `TAG_UNARY`：

  ```c
  先生成 expr
  MINUS → IR_NEG: dst = -expr
  NOT   → IR_NOT: dst = !expr
  ```

- **BuiltinCall / native 调用** `TAG_BUILTIN_CALL`：

  ```c
  先生成每个 args[i]
  IR_NATIVE_CALL:
      dst       = temp_no;
      native_id = b->native_id;
      argc      = b->argc;
      arg_width = type->width;
      args[i]   = args[i]->temp_no;
  ```

### 6.3 逻辑与条件跳转（jumping）

布尔表达式不直接生成“布尔值 temp”，而是通过 `jumping(t, f)` 编码为控制流：

- `And`：

  ```c
  e1.jumping(0, Lfalse);
  e2.jumping(t, f);
  ```

- `Or`：

  ```c
  e1.jumping(Ltrue, 0);
  e2.jumping(t, f);
  ```

- `Not`：

  ```c
  e1.jumping(f, t);
  ```

- `Rel`：

  - 先生成 `e1/e2` 的 temp
  - 如果 `f != 0`，生成一条 `IR_IF_FALSE`，内部用 `relop + src1/src2 + label=f`
  - 同时保留一份字符串形式 `s1 op s2`，交给 `node_emit_jumps()` 做调试输出

### 6.4 语句生成

- **return**：

  ```c
  expr_gen(expr);
  IR_RET: src1 = expr->temp_no;
  ```

- **赋值** `Set`：

  ```c
  expr_gen(expr);
  IR_STORE:
      array_base  = id->offset;
      array_index = 0;
      array_width = id->type->width;
      src1        = expr->temp_no;
  ```

- **数组元素赋值** `SetElem`（仅支持常量下标）：

  ```c
  idx = const_index;
  elem_offset = slot + idx * width;
  expr_gen(expr);
  IR_STORE:
      array_base  = elem_offset;
      array_index = 0;
      array_width = width;
      src1        = expr->temp_no;
  ```

- **顺序语句** `Seq`：

  ```c
  if s1 == Null → 只生成 s2
  if s2 == Null → 只生成 s1
  否则：
      L = newlabel();
      s1.gen(b, L);
      emit_label(L);
      s2.gen(L, a);
  ```

- **if**：

  ```c
  Lthen = newlabel();
  Lelse = newlabel();
  Lend  = newlabel();
  
  expr.jumping(0, Lelse);
  
  emit_label(Lthen);
  stmt.gen(Lthen, a);
  
  IR_GOTO Lend;
  
  emit_label(Lelse);
  emit_label(Lend);
  ```

- **if-else**：

  ```c
  Lthen = newlabel();
  Lelse = newlabel();
  Lend  = newlabel();
  
  expr.jumping(0, Lelse);
  
  emit_label(Lthen);
  stmt1.gen(Lthen, a);
  IR_GOTO Lend;
  
  emit_label(Lelse);
  stmt2.gen(Lelse, a);
  
  emit_label(Lend);
  ```

## 7. 后端：IR → BPF 映射

### 7.1 内存布局（backend_layout）

```c
struct backend_layout {
    int temp_base;      // 临时变量起始 slot（默认 64）
    int temp_count;     // 临时变量数量（默认 64）

    int mem_a;          // 0 → mem_a（8）
    int mem_b;          // 4 → mem_b（16）
    int mem_c;          // 8 → mem_c（24）

    int mem_arr_base[4];// 12/16/20/24 → 32/40/48/56
};
```

映射函数：

```c
int temp_slot(const struct backend_layout *l, int t)
    => l->temp_base + t * 4;

int map_array_base(const struct backend_layout *l, int base)
    // 0/4/8/12/16/20/24 → mem_a/mem_b/mem_c/mem_arr_base[i]
```

前端/IR 中所有 `offset/slot` 都是逻辑值（0,4,8,...），后端统一映射到 BPF `mem[]` 槽位。

### 7.2 指令选择（selection）

- **IR_MOVE**：

  ```c
  LD  #imm
  ST  MEM[temp_slot(dst)]
  ```

- **IR_ADD/SUB/MUL/DIV**：

  ```c
  LD   MEM[temp_slot(src1)]
  LDX  MEM[temp_slot(src2)]
  ALU{ADD/SUB/MUL/DIV} X
  ST   MEM[temp_slot(dst)]
  ```

- **IR_LOAD**（局部变量/数组）：

  ```c
  base_slot = map_array_base(array_base) + array_index;
  LD  MEM[base_slot]
  ST  MEM[temp_slot(dst)]
  ```

- **IR_STORE**：

  ```c
  src_slot  = temp_slot(src1);
  base_slot = map_array_base(array_base) + array_index;
  
  LD  MEM[src_slot]
  ST  MEM[base_slot]
  ```

- **IR_LOAD_CTX**：

  ```c
  // ctx 在 BPF VM 中作为 ABS 访问空间
  switch (width):
    1 → LD B ABS offset
    2 → LD H ABS offset
    4 → LD W ABS offset
  ST MEM[temp_slot(dst)]
  ```

- **IR_RET**：

  ```c
  LD  MEM[temp_slot(src1)]
  RET A
  ```

- **IR_NATIVE_CALL**（关键 ABI）：

  - 先把参数从 temp_slot 读出，按约定写入 BPF VM 的“参数槽”（通过 `BPF_ST` 固定 offset）

  - 然后：

    ```c
    BPF_STMT(BPF_MISC | BPF_COP, native_id);
    ```

    触发 VM 侧的 native 分发逻辑（`native_id` 作为 COP 编号）

  - 最后：

    ```c
    ST MEM[temp_slot(dst)]
    ```

    把返回值从 A 寄存器写回 temp 槽。

- **控制流**：`IR_IF_FALSE / IR_GOTO / IR_LABEL`

  - 由 `lower_if_false / lower_goto / lower_label` 生成带 `jt/jf/k` 的 BPF 跳转
  - `patch_jumps()` 在所有 IR 降级完成后，根据 `label_pc[]` 回填跳转目标 PC

## 8. 编译器总结

- **AST 显式建模控制流与布尔逻辑**：
  通过 `gen/jumping` 双接口，把“表达式值”和“控制流”分开编码，短路逻辑、关系运算都在 AST 层展开。
- **IR 简单、稳定、接近三地址码**：
  所有运算都围绕 `dst/src1/src2` 和“逻辑栈帧 offset”展开，方便后端做简单映射。
- **后端布局固定、可预测**：
  通过 `backend_layout` 把 temp / 局部变量 / 数组 / ctx 映射到 BPF `mem[]`，使得 VM 侧可以用固定约定解释程序状态。
- **native 调用 ABI 明确**：
  编译器只关心 `native_id + argc + args temp_no`，具体参数槽布局和调用逻辑完全由 VM 侧实现，保持前后端解耦。



#  ccBPF 虚拟机设计文档

## 1. 虚拟机总体结构

ccbpf 的虚拟机由三部分组成：

1. **cbpf 执行器（`ccbpf_vm_exec`）**
   - 这是一个 4.4BSD-lite 风格的经典 BPF 解释器
   - 支持 A/X 寄存器、mem[] scratch 区、ABS/IND 加载、ALU、跳转、RET 等
2. **ccbpf 程序加载器（`ccbpf_load_from_memory`）**
   - 负责解析 `.ccbpf` 镜像
   - 加载 BPF 指令、字符串池、map 数组、入口点等
3. **hook 系统（`hook_register / hook_attach / hook_run`）**
   - 允许用户动态注册 hook
   - attach 多个程序
   - hook 触发时顺序执行所有程序

# 2. cbpf 虚拟机执行模型

虚拟机入口：

```c
unsigned int ccbpf_vm_exec(struct ccbpf_program *prog,
                           struct bpf_insn *pc,
                           unsigned char *p,
                           unsigned int wirelen,
                           unsigned int buflen);
```

### 2.1 寄存器模型

VM 只有两个寄存器：

- `A`：累加器（主寄存器）
- `X`：索引寄存器

初始化：

```c
uint32_t A = 0, X = 0;
```

### 2.2 scratch 内存（mem[]）

```c
#define CCBPF_STACK_SIZE (10*1024)
uint8_t mem[CCBPF_STACK_SIZE];
```

scratch 区用于：

- 临时变量（temp_slot）
- 局部变量（map_array_base）
- native 调用参数槽（mem[0], mem[4]）
- IR_LOAD / IR_STORE 映射的所有“逻辑栈帧”

VM 每次执行前会清空：

```c
memset(mem, 0, sizeof(mem));
```

# 3. 指令语义

VM 支持完整的 classic BPF 指令集：

### 3.1 加载指令（LD / LDX）

- **ABS 模式**：从 frame（ctx）读取

```c
BPF_LD | BPF_W | BPF_ABS   → A = *(uint32_t*)(p + k)
BPF_LD | BPF_H | BPF_ABS   → A = *(uint16_t*)(p + k)
BPF_LD | BPF_B | BPF_ABS   → A = p[k]
```

- **IND 模式**：从 `p[X + k]` 读取
- **IMM 模式**：

```c
BPF_LD  | BPF_IMM → A = k
BPF_LDX | BPF_IMM → X = k
```

- **MEM 模式**：

```c
BPF_LD  | BPF_MEM → A = mem[k]
BPF_LDX | BPF_MEM → X = mem[k]
```

### 3.2 存储指令（ST / STX）

```c
BPF_ST  → mem[k] = A
BPF_STX → mem[k] = X
```

### 3.3 算术指令（ALU）

支持：

- ADD / SUB / MUL / DIV
- AND / OR
- LSH / RSH
- NEG

支持立即数和 X 寄存器两种形式。

### 3.4 跳转指令（JMP）

支持：

- 无条件跳转：`JA`
- 比较跳转：`JGT/JGE/JEQ/JSET`（支持 K 和 X）
- `jt/jf` 分支偏移

### 3.5 返回指令（RET）

```c
BPF_RET | BPF_K → return k
BPF_RET | BPF_A → return A
```

# 4. native 调用机制（BPF_COP）

这是 ccBPF 的关键扩展。

### 4.1 IR_NATIVE_CALL → BPF_COP

后端生成：

```c
BPF_MISC | BPF_COP, k = native_id
```

VM 执行时：

```c
case BPF_MISC | BPF_COP: {
    int func_id = pc->k;
    struct native_entry *e = hashmap_get(&native_table, func_id);
```

### 4.2 参数 ABI

VM 侧约定：

- `A` → a0
- `X` → a1
- `mem[0]` → a2
- `mem[4]` → a3

代码：

```c
uint32_t a0 = A;
uint32_t a1 = X;
uint32_t a2 = mem[0];
uint32_t a3 = mem[4];
```

### 4.3 native 函数签名

```c
typedef uint32_t (*native_fn_t)(struct ccbpf_program *prog,
                                uint32_t a0, uint32_t a1,
                                uint32_t a2, uint32_t a3);
```

### 4.4 注册 native

```c
void native_register(int func_id, int argc, native_fn_t fn)
```

native 存在 `native_table`（hashmap）中。

# 5. hook 系统设计

hook 系统允许用户动态注册 hook，并 attach 多个程序。

### 5.1 hook_entry 结构

```c
struct hook_entry {
    const char *name;
    struct hook_node *head;
};

struct hook_node {
    struct ccbpf_program *prog;
    struct hook_node *next;
};
```

### 5.2 注册 hook

```c
void hook_register(const char *name)
```

- 分配 `hook_entry`
- 插入 `hook_table`（hashmap）

### 5.3 attach 程序

```c
int hook_attach(const char *hook_name, uint8_t *image, size_t len)
```

流程：

1. 找到 hook_entry
2. `ccbpf_load_from_memory(image)` 加载程序
3. 插入链表头（head 插入法）
4. 程序立即生效

### 5.4 detach 程序

```c
int hook_detach(const char *hook_name)
```

- 卸载所有程序（逐个 `ccbpf_unload`）
- 清空链表

### 5.5 hook_run

```c
uint32_t hook_run(const char *hook_name, uint8_t *frame, size_t frame_size)
```

- 顺序执行链表中的所有程序
- 返回最后一个程序的返回值

# 6. `.ccbpf` 文件格式

由 `ccbpf_load_from_memory()` 可知：

```c
struct CCBPF_Header {
    uint32_t magic;
    uint32_t code_offset;
    uint32_t code_size;
    uint32_t data_offset;
    uint32_t data_size;
    uint32_t entry;
};
```

加载流程：

1. 校验 magic
2. 复制 `.text`（BPF 指令）
3. 解析 `.data`（字符串池）
4. 初始化 `maps[]`（8 个 hashmap）
5. 设置入口点 `entry`

# 7. 程序执行流程

完整执行链路：

```
.ccbpf 镜像
    ↓ ccbpf_load_from_memory
ccbpf_program { insns, strings, maps, entry }
    ↓ hook_attach
hook_entry 链表
    ↓ hook_run
ccbpf_run_frame
    ↓
ccbpf_vm_exec
    ↓
BPF 指令解释执行
    ↓
native 调用（BPF_COP）
    ↓
返回 uint32_t
```

# 8. 虚拟机设计总结

ccbpf 的 VM 具有以下特点：

- **完全兼容 classic BPF**（4.4BSD-lite）
- **scratch mem[] 作为统一的“虚拟栈帧”**
- **ctx 访问通过 ABS 模式完成**
- **native 调用通过 BPF_COP 实现**
- **hook 系统允许动态 attach/detach 程序**
- **程序加载器支持字符串池与 map 数组**

整个 VM 设计非常小巧、可移植、可嵌入 MCU/RTOS，也可以在 Linux 用户态运行。
