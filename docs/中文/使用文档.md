# ccbpf 用户手册

ccbpf 由两个主要组件组成：**编译器（compiler）** 和 **虚拟机（VM）**。

推荐的使用方式是：在资源充足的节点上运行编译器，将编译后的程序发送到目标节点，由目标节点使用 VM 执行程序。

# **ccbpf C 子集规范**

ccbpf 使用一个受限的 C 语言子集作为源语言。
 该子集专门为 **安全、可验证、可预测的内核 hook 程序** 设计，其语法由编译器前端严格定义。

本规范描述了 ccbpf 支持的所有语法特性。

# **设计目标**

ccbpf C 子集的设计目标是：

- **可验证（Verifiable）**：无循环、无指针算术、无复杂控制流
- **可预测（Predictable）**：所有内存访问在编译期可知
- **可映射（Mappable）**：语法可直接映射到 BPF 指令
- **安全（Safe）**：ctx 访问严格受限
- **可移植（Portable）**：适用于 MCU 环境

# **1. 程序结构**

一个 ccbpf 程序必须包含 **且仅包含一个** 入口函数：

```c
int hook(void *ctx)
{
    ...
}
```

要求：

- 函数名必须是 `hook`
- 返回类型必须是 `int`
- 参数必须是 `void *ctx`
- 不允许定义其他函数
- 不支持递归、函数指针、可变参数

# **2. 类型系统**

ccbpf 支持以下类型。

## **2.1 基本类型**

由于 VM 当前不支持有符号算术，`unsigned int` 与 `int` 行为完全一致。
 有符号语义保留用于未来扩展。

### **整数语义（重要）**

ccbpf VM 基于 classic BPF，因此所有算术与比较均使用 **无符号语义**：

- `int` 等同于 `uint32_t`
- `short` 等同于 `uint16_t`
- `char` 等同于 `uint8_t`
- 所有比较均为无符号比较
- 所有右移均为逻辑右移
- 所有算术均为无符号算术
- `(int)/(short)/(char)` 等 cast **不会改变符号语义**

| 类型             | 宽度 | 语义     |
| ---------------- | ---- | -------- |
| `int`            | 4    | unsigned |
| `bool`           | 1    | unsigned |
| `char`           | 1    | unsigned |
| `short`          | 2    | unsigned |
| `unsigned int`   | 4    | unsigned |
| `unsigned short` | 2    | unsigned |
| `unsigned char`  | 1    | unsigned |

## **2.2 指针类型**

ccbpf 支持任意层级的指针声明：

```c
int *p;
struct hdr *h;
unsigned char **pp;
```

限制：

- 不支持指针算术（如 `p+1`, `p++`）
- 不支持解引用（`*p`）
- 指针主要用于 **从 ctx 派生出的结构体指针**

## **2.3 数组**

```c
int a[10];
char buf[32];
```

规则：

- 数组大小必须是常量
- 支持 `a[i]`
- 不支持多维数组

## 2.4 结构体类型

支持结构体定义：

```c
struct udp_hdr {
    unsigned short sport;
    unsigned short dport;
};
```

支持：

- 多个字段
- 字段宽度自动累加
- 字段偏移由编译器计算

不支持：

- 嵌套结构体
- 结构体赋值
- 结构体作为局部变量（仅支持指针）

## **2.5 结构体指针**

支持：

```c
struct udp_hdr *uh;
uh->sport;
```

但仅当其来源于：

```c
(struct T *)&ctx[offset]
```

# **3. ctx 访问模型（核心）**

ccbpf 的核心语义是 **ctx 访问**。

## **3.1 ctx 数组访问**

```c
ctx[0]
ctx[12]
```

规则：

- 下标必须是编译期常量
- 仅用于派生结构体指针

## **3.2 ctx → 结构体指针**

```c
struct udp_hdr *uh = (struct udp_hdr *)&ctx[0];
```

编译器将：

- 记录结构体类型
- 记录基地址 offset
- 允许 `uh->field` 访问

## **3.3 ctx 字段访问**

```c
x = uh->sport;
```

编译器会将其降低为：

```
ctx_load(offset + field_offset)
```

ccbpf 支持以下表达式：

## **4.2 比较表达式**


## **4.3 逻辑表达式**

## **4.4 位运算**

## **4.5 一元运算**


- `&expr` 仅允许 `&ctx[constant]`

# **6. Native 函数（用户注册）**

ccbpf 允许用户注册 **可从程序中调用的函数**。
 编译器仅将其视为“符号 + 参数数量”，实际实现由 VM 提供。

Native 函数构成一个 **用户自定义 ABI**。

# **6.1 Native 函数工作机制（重要）**

整个机制分为两部分：

## **（1）编译器侧：声明 Native 函数**

你告诉编译器：

- 函数名（字符串）
- 函数 ID（`func_id`）
- 参数数量（`argc`）

示例：

```c
native_decl_register("print", 3, 1);
native_decl_register("map_update", 6, 3);
native_decl_register("now_ms", 7, 0);
```

编译器会：

- 识别函数名
- 检查参数数量
- 在 IR 中生成 `NATIVE_CALL func_id=3 argc=1`
- **不关心实现**

## **（2）VM 侧：实现 Native 函数**

你必须写一个 wrapper：

```c
uint32_t native_print(struct ccbpf_program *p,
                      uint32_t a0,
                      uint32_t a1,
                      uint32_t a2,
                      uint32_t a3)
{
    printf("%u", a0);
    return 0;
}
```

并注册：

```c
native_register(3, 1, native_print);
```

VM 负责：

- 根据 `func_id` 查找函数
- 按 `argc` 传递参数
- 调用 wrapper
- 返回结果

# **6.2 参数传递机制**

ccbpf 始终使用 **四个参数槽**：

```
a0, a1, a2, a3
```

如果声明：

```c
map_update(mapid, key, value)
```

编译器生成：

```
a0 = mapid
a1 = key
a2 = value
```

VM 调用：

```c
native_map_update(p, a0, a1, a2, a3);
```

**未使用的参数始终为 0。**

# **6.3 字符串机制**

字符串字面量：

```c
print_str("hello");
```

编译器将 `"hello"` 放入 **字符串池**，并替换为字符串 ID：

```
print_str(0);   // 0 是 "hello" 的 ID
```

VM wrapper：

```c
uint32_t native_print_str(struct ccbpf_program *p,
                          uint32_t a0,
                          uint32_t a1,
                          uint32_t a2,
                          uint32_t a3)
{
    if (a0 >= p->string_count)
        return 0;

    printf("%s", p->strings[a0]);
    return 0;
}
```

含义：

- **`a0` 是字符串 ID**
- **`p->strings[a0]` 是实际字符串**

# **6.4 Map 机制**

Map 是简单的键值存储。

### **查找**

```c
uint32_t map_lookup(uint32_t mapid, uint32_t key);
```

VM：

```c
void *val_ptr = hashmap_get(&p->maps[map_id], key);
return val_ptr ? (uint32_t)val_ptr : 0;
```

### **更新**

```c
void map_update(uint32_t mapid, uint32_t key, uint32_t value);
```

VM：

```c
hashmap_put(&p->maps[map_id], key, value);
```

特点：

- key 和 value 均为 32 位整数
- 不支持复杂类型
- 不支持删除（可用 value=0 作为替代）

# **6.5 示例：编写一个 Native 函数**

假设你想添加：

```c
add(a, b)
```

## **编译器侧**

```c
native_decl_register("add", 10, 2);
```

## **VM 侧**

```c
uint32_t native_add(struct ccbpf_program *p,
                    uint32_t a0,
                    uint32_t a1,
                    uint32_t a2,
                    uint32_t a3)
{
    return a0 + a1;
}

native_register(10, 2, native_add);
```

## **用户 C 程序**

```c
int hook(void *ctx)
{
    return add(10, 20);
}
```

# **示例程序**

```c
struct udp_hdr {
    unsigned short sport;
    unsigned short dport;
};

int hook(void *ctx)
{
    struct udp_hdr *uh = (struct udp_hdr *)&ctx[0];
```

# **将 C 源码编译为 `.ccbpf` 程序**

ccbpf 的完整编译流水线如下：

- 输入：一段 C 源代码
- 输出：一个可加载的 `.ccbpf` 程序镜像
- 步骤：**词法分析 → 语法分析 → IR → BPF → 打包 →（可选）写入文件系统**

## **提供 C 源代码**

你可以从文件或任何输入方式获取 C 源码字符串：

```c
const char *src =
    "struct udp_hdr {\n"
    "    unsigned short sport;\n"
    "    unsigned short dport;\n"
    "};\n"
    "\n"
    "int hook(void *ctx)\n"
    "{\n"
    "    unsigned int x;\n"
    "    unsigned int y;\n"
    "    struct udp_hdr *uh;\n"
    "\n"
    "    uh = (struct udp_hdr *)&ctx[0];\n"
    "    x = ntohs(uh->sport);\n"
    "    print(x);\n"
    "    y = ntohs(uh->dport);\n"
    "    print(y);\n"
    "    return x + y;\n"
    "}\n";
```

## **初始化编译器**

```c
compiler_init(16, (4*1024), (2*1024));
lexer_set_input_buffer(src, strlen(src));
```

说明：

- `compiler_init()` 初始化前端、IR、后端的内存池
  - `16` 是最大内存块大小（2^15）
  - 第二个参数配置前端内存池
  - 第三个参数配置 IR 内存池
- `lexer_set_input_buffer()` 设置输入源码

## **词法分析**

```c
struct lexer lex;
lexer_init(&lex);
```

## **语法分析（生成 AST）**

```c
struct Parser *p = parser_new(&lex);
parser_program(p);
```

## **清理前端资源（推荐）**

```c
frontend_destroy(&lex);
```

## **IR 阶段**

```c
struct ir_mes im;
ir_mes_get(&im);
```

此时，IR 已由 parser 完全生成。

## **IR → BPF 指令降级**

```c
struct bpf_builder b;
bpf_builder_init(&b, (3*1024));

ir_lower_program(im.ir_head, im.label_count, &b);

struct bpf_insn *prog = bpf_builder_data(&b);
int prog_len = bpf_builder_count(&b);
```

说明：

- `ir_lower_program()` 将 IR 降级为 BPF 指令序列
- `bpf_builder_data()` 获取最终 BPF 程序
- `bpf_builder_count()` 获取指令数量

## **打包为 `.ccbpf` 可执行镜像**

```c
size_t image_len = 0;
uint8_t *image = ccbpf_pack_memory(prog, (size_t)prog_len, &image_len);

printf("=== CCBPF IMAGE READY ===\n");
printf("Image at %p, size = %u bytes\n", image, (unsigned)image_len);
```

`ccbpf_pack_memory()` 会生成一个可加载的 `.ccbpf` 程序镜像。

## **释放资源**

```c
bpf_builder_free(&b);
```

## **完整使用示例**

```c
int main(void)
{
    // C source code to compile
    const char *src =
        "struct udp_hdr {\n"
        "    unsigned short sport;\n"
        "    unsigned short dport;\n"
        "};\n"
        "\n"
        "int hook(void *ctx)\n"
        "{\n"
        "    unsigned int x;\n"
        "    unsigned int y;\n"
        "    struct udp_hdr *uh;\n"
        "\n"
        "    uh = (struct udp_hdr *)&ctx[0];\n"
        "    x = ntohs(uh->sport);\n"
        "    print(x);\n"
        "    y = ntohs(uh->dport);\n"
        "    print(y);\n"
        "    return x + y;\n"
        "}\n";

    // Initialize compiler memory pools
    compiler_init(16, (4*1024), (2*1024));
    lexer_set_input_buffer(src, strlen(src));

    // Lexing
    struct lexer lex;
    lexer_init(&lex);

    // Parsing (build AST)
    struct Parser *p = parser_new(&lex);
    parser_program(p);

    // Free frontend resources
    frontend_destroy(&lex);

    // IR → BPF lowering
    struct bpf_builder b;
    bpf_builder_init(&b, (3*1024));

    struct ir_mes im;
    ir_mes_get(&im);

    ir_lower_program(im.ir_head, im.label_count, &b);

    struct bpf_insn *prog = bpf_builder_data(&b);
    int prog_len = bpf_builder_count(&b);

    // Package into .ccbpf image
    size_t image_len = 0;
    uint8_t *image = ccbpf_pack_memory(prog, (size_t)prog_len, &image_len);

    printf("=== CCBPF IMAGE READY ===\n");
    printf("Image at %p, size = %u bytes\n", image, (unsigned)image_len);

    // Cleanup
    bpf_builder_free(&b);

    return 0;
}
```

# **VM 使用方式**

ccbpf 虚拟机提供以下运行时能力：

- 从内存（或文件）加载 `.ccbpf` 程序
- 卸载程序并释放资源
- 使用给定 frame/ctx 执行程序
- 将程序 attach 到 hook
- 当 hook 触发时执行所有 attach 的程序

VM 是 ccbpf 程序的执行环境。

## **结构概览**

### **struct ccbpf_program**

```c
struct ccbpf_program {
    struct bpf_insn *insns;   // 指令序列
    size_t insn_count;        // 指令数量

    char **strings;           // 字符串常量池
    int string_count;

    void *data;               // 预留扩展
    size_t data_size;

    size_t map_count;         // map 数量
    struct hashmap maps[CCBPF_MAX_MAPS];

    uint32_t entry;           // 入口偏移
};
```

# **API 概览**

| API                        | 描述                         |
| -------------------------- | ---------------------------- |
| `ccbpf_load_from_memory()` | 从内存加载 `.ccbpf` 程序     |
| `ccbpf_load()`             | 从文件系统加载 `.ccbpf` 程序 |
| `ccbpf_unload()`           | 卸载程序并释放资源           |
| `ccbpf_run_frame()`        | 使用 ctx 执行程序            |
| `hook_attach()`            | 将程序 attach 到 hook        |
| `hook_detach()`            | 从 hook detach 所有程序      |
| `hook_run()`               | 执行 hook 上的所有程序       |

下面是每个 API 的详细说明。

# **ccbpf_load_from_memory()**

```c
struct ccbpf_program *ccbpf_load_from_memory(const uint8_t *image, size_t len);
```

### 描述

从内存中的 `.ccbpf` 镜像加载程序。

### 参数

| 名称  | 类型      | 描述          |
| ----- | --------- | ------------- |
| image | uint8_t * | `.ccbpf` 镜像 |
| len   | size_t    | 镜像长度      |

### 返回值

- 成功：`struct ccbpf_program *`
- 失败：`NULL`

# **ccbpf_unload()**

```c
void ccbpf_unload(struct ccbpf_program *p);
```

### 描述

释放程序的所有资源：

- 指令内存
- 字符串池
- maps
- 程序结构体本身

# **ccbpf_run_frame()**

```c
uint32_t ccbpf_run_frame(struct ccbpf_program *prog,
                         void *frame,
                         size_t frame_size);
```

### 描述

使用给定 frame（ctx）执行程序入口点。

### 返回值

- 程序返回的 32 位整数

# **hook_attach()**

```c
int hook_attach(const char *hook_name, uint8_t *image, size_t len);
```

### 描述

将 `.ccbpf` 程序 attach 到指定 hook。

# **hook_detach()**

```c
int hook_detach(const char *hook_name);
```

### 描述

从 hook detach **所有** 程序。

# **hook_run()**

```c
uint32_t hook_run(const char *hook_name, uint8_t *frame, size_t frame_size);
```

### 描述

执行 hook 上 attach 的所有程序，按链表顺序执行。

返回值为 **最后一个程序的返回值**。

# **典型运行时流程**

```c
// 1. Load program from memory or file
struct ccbpf_program *p = ccbpf_load("/prog.ccbpf");

// 2. Attach to a hook
hook_attach("hook_udp_input", image, image_len);

// 3. Execute when the hook is triggered
uint32_t r = hook_run("hook_udp_input", frame, frame_size);

// 4. Detach and unload
hook_detach("hook_udp_input");
ccbpf_unload(p);
```

# **7. Hook 机制（动态注册）**

ccbpf 的 hook 系统是 **完全动态的**。
 VM 不再使用固定的 hook 列表，用户可以在运行时注册新的 hook。

# **7.1 注册 Hook**

```c
void hook_register(const char *name)
{
    struct hook_entry *e = heap_malloc(sizeof(*e));
    e->name = heap_strdup(name);
    e->head = NULL;

    hashmap_put(&hook_table, (void*)e->name, e);
}
```

该函数：

- 创建一个新的 `hook_entry`
- 插入 `hook_table`
- 初始无 attach 程序（`head = NULL`）

# **7.2 Hook 结构**

当前的 `hook_entry` 结构：

```c
struct hook_entry {
    const char *name;
    struct ccbpf_program *head;   // 链表头
};
```

说明：

- `name` 是 hook 名称
- `head` 是 attach 的程序链表
- 一个 hook 可以 attach 多个程序
- 程序按链表顺序执行

# **7.3 将程序附加到 Hook（Attaching a Program to a Hook）**

如果节点 A 发送：

```
attach hook_udp_input out.ccbpf
```

那么节点 B 将会：

- 查找对应的 `hook_entry`
- 将程序插入到链表的头部（或尾部）
   *（你当前的实现是插入到链表头部）*
- 程序立即生效

# **7.4 移除程序（Detaching Programs）**

### **1.从 hook 中移除所有程序**

```
detach hook_udp_input
```

# 7.5 Hook 执行流程（Hook Execution Flow）

当一个 hook 被触发时：

```c
struct hook_entry *e = hashmap_get(&hook_table, name);
for (prog = e->head; prog; prog = prog->next) {
    ccbpf_run(prog, ctx);
}
```

特点：

- 多个程序按顺序依次执行
- 每个程序接收相同的 ctx
- 每个程序拥有自己的 map 存储空间
- 程序之间互不干扰

# **7.6 示例：注册一个新的 Hook**

假设你想为文件系统添加 hook：

```c
hook_register("hook_fs_open");
hook_register("hook_fs_close");
```

然后用户可以写：

```c
int hook(void *ctx)
{
    print_str("file opened\n");
    return 0;
}
```

并附加它：

```
attach hook_fs_open out.ccbpf
```

# **使用示例（Usage Example）**

你可以在系统的任何位置放置 hook —— 例如调度器或协议处理器内部。

当没有程序附加时，返回值默认为系统定义的行为。

```c
uint32_t udp_input(uint8_t *frame, size_t frame_size)
{
    // 在这里触发 hook
    uint32_t ret = hook_run("hook_udp_input", frame, frame_size);

    // 正常的 UDP 输入处理逻辑
}
```

另一个例子：

```c
void task_switch_context(void)
{
    // 模拟一个 UDP 包事件
    uint8_t pkt[64];
    struct udp_hdr *uh = (struct udp_hdr *)pkt;

    uh->sport = htons(10000);
    uh->dport = htons(20000);
    uh->len   = htons(20);
    uh->checksum = 0;

    // 假设该包进入 UDP 输入路径
    uint32_t ret = udp_input(pkt, 20);

    // 调度器逻辑继续...
}
```

如果我们编译并附加如下程序：

```c
const char *src =
            "struct udp_hdr {\n"
            "    unsigned short sport;\n"
            "    unsigned short dport;\n"
            "};\n"
            "\n"
            "int hook(void *ctx)\n"
            "{\n"
            "    unsigned int x;\n"
            "    unsigned int y;\n"
            "    struct udp_hdr *uh;\n"
            "\n"
            "    uh = (struct udp_hdr *)&ctx[0];\n"
            "    x = ntohs(uh->sport);\n"
            "    print(x);\n"
            "    y = ntohs(uh->dport);\n"
            "    print(y);\n"
            "    return x + y;\n"
            "}\n";
```

然后附加它：

```c
if (hook_attach("hook_udp_input", image, size) != 0) {
    printf("hook_attach failed\n");
    heap_free(image);
    return 0;
}
```

返回值将变为 **30000**（10000 + 20000）。

你也可以 detach 程序以恢复正常行为：

```c
hook_detach("hook_udp_input");
```
